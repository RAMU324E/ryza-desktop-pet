# Ryza Desktop Pet 使用指南

本文面向日常使用和本机配置。项目架构、资产、开发与构建信息见根目录 [README.md](../README.md)。

## 1. 安装与启动

### 1.1 安装

运行：

```text
desktop\src-tauri\target\release\bundle\nsis\Ryza Desktop Pet_0.1.0_x64-setup.exe
```

当前安装包未签名。若 Windows SmartScreen 显示“未知发布者”，先确认安装包确实来自本项目构建，再选择“更多信息 → 仍要运行”。

安装后从开始菜单或安装目录启动 **Ryza Desktop Pet**。应用会同时启动本机 Moka 与 Clonoth sidecars，监听：

```text
http://127.0.0.1:18766
ws://127.0.0.1:18766/moka
http://127.0.0.1:18767  （Clonoth Supervisor）
```

两个 sidecar 都只监听回环地址，不直接接受局域网或互联网连接。

### 1.2 窗口与托盘

- **移动桌宠**：拖动主窗口顶部的橙色短条。
- **显示/收起聊天**：点击主窗口右下角聊天按钮；输入框有焦点时抽屉保持显示。
- **打开设置**：点击聊天标题右侧“⚙ 设置”，或使用托盘“设置”。
- **隐藏/显示**：使用托盘“隐藏”或“显示”。
- **关闭窗口**：右上角关闭只会隐藏，不会退出进程。
- **完整退出**：托盘 → “退出”。这会同时关闭 Tauri、Moka 和 Clonoth/Engine 进程树。

主桌宠窗口无系统标题栏、无阴影和原生白边；设置窗口保留普通 Windows 边框。如果更新后仍看到旧白边，请先从托盘退出旧进程，再启动新安装版本。

## 2. 第一次配置

配置页底部有“测试 LLM”“测试并播放 TTS”和“保存并立即生效”。推荐按以下顺序操作。

### 2.1 配置 LLM

最低必填项：

| 字段 | 说明 |
|---|---|
| 配置名称 | 只用于界面和错误提示，可自定义 |
| API 模式 | `Auto`、`Chat Completions` 或 `Responses`；Auto 按 URL 判断 |
| HTTP Method | 常见为 `POST` |
| 精确 API URL | 完整 `chat/completions` 或 `responses` 地址，不会自动补路径 |
| API Key | Provider 凭据；留空时不自动添加 Authorization |
| 模型名 | 上游实际接受的模型 ID |

高级字段：

- **自定义请求头 JSON**：必须是 JSON 对象；同名字段覆盖默认 Header。
- **额外请求体 JSON**：必须是 JSON 对象；同名字段覆盖默认请求体字段。
- **开启推理**：向兼容 Provider 发送 `thinking` 设置。
- **推理强度**：自由文本，是否支持取决于 Provider。
- **Temperature / Max tokens**：生成参数。
- **response_format=json_object**：建议对支持 OpenAI JSON mode 的模型启用。

当 Key 非空、Headers 又没有显式 Authorization 时，应用自动添加：

```text
Authorization: Bearer <Key>
```

若 Provider 使用其他鉴权格式，请在 Headers 中完整填写；应用不会覆盖已有 Authorization。

点击“测试 LLM”。看到连接成功后再保存。测试失败时，错误区会显示 Provider 名、HTTP 状态和截断后的响应正文，但不会主动显示请求 Header。

#### 对话 Agent、视觉和 MCP

- **对话 Agent**：推荐 `Clonoth`，提供持久会话、长期记忆、自动记忆提取/dream、取消和 MCP；`Direct` 只保留为兼容/故障回退。
- **独立视觉 Provider**：启用后填写完整 Chat Completions 或 Responses URL、Key 和视觉模型。不开启时，截图消息会回到主文本节点处理。
- **搜索 MCP**：当前支持一个 Streamable HTTP MCP。Headers 必须是 JSON 对象；只配置可信服务，MCP 工具结果会进入模型上下文。
- 保存这些设置会同步 Clonoth 配置，并在必要时热重载 Provider 配置和 MCP 工具；不会重启进程，也不会清除已有长期记忆。

### 2.2 选择回复/朗读语言

设置页的“回复 / 朗读语言模式”有两种：

- **中文回复 → 中文语音**：聊天文本和送往 TTS 的文本都是中文。
- **中文回复 → 日语语音**：聊天和历史仍显示中文；每段送入 TTS 前用当前 LLM 翻译成日语，并向支持的 TTS 模板发送 `ja`。

日语语音模式会多一次 LLM 翻译调用，因此延迟和调用量会增加。HF 预设会把 `zh_ryza` / `zh_ryza_asmr` 自动切换为对应的日语 voice ID。

### 2.3 配置 TTS

设置页可以选择当前 Profile，也可以新增、复制、删除或用快捷预设创建 Profile。至少保留一个 Profile。

通用字段：

| 字段 | 说明 |
|---|---|
| Adapter | 选择响应协议解析器 |
| 精确 API URL / Method | 上游完整接口地址和方法 |
| Key | 可选；鉴权规则随 Adapter 处理 |
| 模型名 / 声线 | 可供请求体模板引用 |
| 请求头 JSON | 必须是 JSON 对象 |
| 请求体模板 | 运行时替换文本、模型、声线和语言 |
| Content-Type | 期望响应类型 |
| PCM Format / Sample rate / Channels | raw PCM 或协议缺少元数据时使用 |
| Concurrency | 此 Profile 的并发合成数 |
| 流式响应 | 是否按流处理响应 |

支持的模板占位符：

```text
{{JSON.stringify(speakText)}}
{{JSON.stringify(text)}}
{{JSON.stringify(model)}}
{{JSON.stringify(voice)}}
{{JSON.stringify(instruction)}}
{{JSON.stringify(speechLanguage)}}
```

占位符会生成合法 JSON 字面量，不要再在外层重复加引号。例如：

```json
{"text":{{JSON.stringify(speakText)}},"language":{{JSON.stringify(speechLanguage)}}}
```

#### MiMo SSE

选择 `mimo-sse`。预设使用 OpenAI 风格请求和 SSE 响应，从 `choices[0].delta.audio.data` 读取 base64 PCM。MiMo Key 通常放在 Profile 的 Key 字段，应用按该 Adapter 使用 `api-key` Header。

#### HF 莱莎云端

选择 `http-wav`。预设请求 `POST /v1/tts`，接收完整 WAV。需要鉴权时，在 Key 字段填写凭据；应用会自动使用 Bearer Authorization，除非 Headers 已经提供。

默认 ASMR voice 为 `zh_ryza_asmr`。切换日语语音模式时会改用 `ja_ryza_asmr`。

#### 本地 GPT-SoVITS v2

选择 `gpt-sovits-stream`，默认地址：

```text
http://127.0.0.1:9880/tts
```

使用前必须先启动 GPT-SoVITS API v2。根据本地模型填写请求模板中的：

- `ref_audio_path`
- `prompt_lang`
- `prompt_text`
- `text_lang`
- `media_type`
- `streaming_mode`

流式 WAV 模式应使用 `media_type: "wav"` 和 `streaming_mode: true`；服务首块返回 WAV header，后续返回 PCM。也可使用 raw。当前应用不解码 OGG/AAC TTS 响应。

#### 自定义 raw PCM

选择 `raw-pcm`，并准确填写 `format / sampleRate / channels`。响应体必须只有连续 PCM，不应带 WAV header 或 JSON 包装。

点击“测试并播放 TTS”。听到测试语音后再保存。

### 2.4 嘴型参数

默认推荐值：

| 参数 | 推荐 | 作用 |
|---|---:|---|
| 嘴型灵敏度 | 1.6 | 音量映射到开口幅度 |
| 张嘴响应 | 90 ms | 开口跟随速度 |
| 闭嘴响应 | 150 ms | 闭口跟随速度 |
| 开始/结束过渡 | 140 ms | 语音接管和释放嘴型的混合时间 |

嘴型过小先提高灵敏度；抖动明显先增加闭嘴响应；起止突兀再增加过渡。不要一次同时大幅修改所有参数，否则很难判断是哪项产生效果。

## 3. 聊天与表演

### 3.1 基本聊天

1. 打开底部聊天抽屉。
2. 输入消息。
3. `Enter` 发送，`Shift+Enter` 换行。
4. “停止”会中断当前回复和音频。
5. “清空”清除当前页面聊天记录。
6. “语音”复选框控制是否播放 TTS；音量滑块只影响播放音量。
7. 点击截图按钮会打开 Windows 系统选区；完成选区后，图片只附加到下一条消息。

应用不会自动截图、定时截图或读取摄像头。每条消息还会附带最近一次非 Ryza 前台应用的进程名和窗口标题；这可能包含敏感标题，发送前请留意当前窗口。

Clonoth 先生成自然语言主回复，再由独立低温度规划器选择当前模型允许的情绪、表情、视线和最多 3 段动作。运行时强制保持主回复文字逐字不变，并丢弃动作目录以外的 ID。

### 3.2 连续动作 beats

明确要求“连续表演”“先……再……”时，LLM 可以生成 2～3 段 beats。例如：

```text
先挥手跟我打招呼，再做一个胜利姿势，每个动作配一句话。
```

每段短句开始时触发该段动作。MOKAMOKA 会把动作、情绪、视线和保持时长转换成跟随语音时间轴的事件。

限制：

- 一轮最多 3 段。
- 每段必须有可朗读的完整短句。
- 动作必须存在于当前姿态的动作目录。
- 站姿/坐姿切换不能和 beats 同轮执行；需要先切姿态，再发下一条动作要求。

### 3.3 姿态切换

可以在设置页手动切换：

- 基础姿态：坐姿（01）/ 站姿（99）
- 坐姿类型：普通 / 盘腿

也可直接聊天：

```text
站起来吧。
坐下吧。
盘腿坐吧。
换回普通坐姿。
```

保存或 LLM 切换后会写入配置，重启仍保持。站姿时坐姿类型暂时不可用；切回坐姿会恢复上次保存的普通/盘腿选择。

动作目录随姿态过滤：普通坐姿、盘腿坐姿和站姿只向 LLM 暴露各自可用动作，减少无效或穿模动作。

### 3.4 触摸、视线和待机

- 角色支持官方 BoundingBox 命中区域和 Tap Reactions。
- 点击不同区域可触发对应反应及触摸语音。
- 视线可跟随鼠标，也可由 LLM 事件切换为看用户、回正、左/右/上/下。
- 基础 idle、轻晃和上下运动使用独立 Spine tracks 混合，叠加动作结束后回到待机。
- 普通坐姿与盘腿使用不同适用动作过滤；盘腿姿态保留专用常驻层。

## 4. 配置文件与备份

配置和 Clonoth 本地数据保存在：

```text
%APPDATA%\RyzaPet\settings.json
%APPDATA%\RyzaPet\clonoth\
```

`settings.json` 包含 LLM/TTS Key、自定义 Headers、系统提示词和角色姿态；`clonoth` 目录包含 Provider/MCP 同步配置、会话、长期记忆、dream、工具状态和截图附件。这些内容都保存在本机，凭据仍为明文。建议：

- 不要把文件发送给别人。
- 不要把文件提交到 Git。
- 截图设置页前遮盖 Key 和 Authorization。
- 更换或撤销凭据后，再删除旧备份。

手动备份：

```powershell
Copy-Item "$env:APPDATA\RyzaPet\settings.json" "$env:APPDATA\RyzaPet\settings.backup.json"
Copy-Item "$env:APPDATA\RyzaPet\clonoth" "$env:APPDATA\RyzaPet\clonoth.backup" -Recurse
```

恢复前先从托盘退出应用，然后覆盖 `settings.json` 和需要恢复的 `clonoth` 目录再启动。不要在应用保存配置或生成回复时手工修改这些文件。

若文件不存在，应用会使用默认配置；开发目录存在 `bridge/settings.json` 时，首次还会从它迁移。迁移完成后以 AppData 文件为准。

## 5. 浏览器控制台

开发环境可运行：

```text
启动聊天软件.bat
```

访问 `http://127.0.0.1:18766/` 后，除聊天外还能看到完整控制台：

- 角色模型切换
- 场景搜索、时段过滤与背景开关
- 基础动作、动作组和全部原始动画测试
- 姿态、视线、触摸反应和 Hit Box 调试
- 情绪、强度和表情部件测试
- Track 调试信息

设置地址：

```text
http://127.0.0.1:18766/settings.html
```

同一时间只运行一个 18766 服务。安装版已启动时，不要再启动浏览器开发 host。

## 6. 常见问题

### 应用启动后没有窗口

- 检查系统托盘，选择“显示”。
- 若托盘已有旧实例，先“退出”再重启。
- 检查 WebView2 Runtime 是否安装。

### 关闭后进程仍在

这是预期行为。窗口关闭会隐藏到托盘。使用托盘“退出”才能结束桌面进程和 sidecar。

### 提示 18766 / 18767 端口被占用

通常是另一个 Ryza 安装版或开发 host 正在运行。先从托盘退出；必要时检查：

```powershell
Get-NetTCPConnection -LocalPort 18766,18767 -ErrorAction SilentlyContinue
```

不要同时运行两套 Moka/Clonoth sidecar。

### LLM 返回 401 / 403

- 检查 Key 是否有效。
- 检查 Provider 要求 Bearer、`api-key` 还是其他 Header。
- 如果 Headers 已写 Authorization，Key 字段不会覆盖它。
- 检查精确 URL 是否属于该 Key 对应的 Provider。

### LLM 返回 402 或余额不足

这是上游账户状态，不是本地解析错误。充值或更换可用凭据/模型。

### LLM 超时

- 降低推理强度或关闭推理。
- 增大 LLM timeout。
- 检查上游模型是否真的支持当前 `thinking` / `reasoning_effort` 字段。
- 当前完整一轮可能包含 Clonoth 主回复和独立表演规划两次模型调用；MOKAMOKA 总等待预算为两次 LLM timeout 加 20 秒，修改设置后立即热更新。

### LLM 有文字但没有动作

- 普通聊天不保证每轮动作。
- 连续表演需要明确写“先……再……”或“连续做两个动作”。
- 当前姿态可能过滤了该动作。
- LLM 编造的动作 ID 会被丢弃，这是防止前端播放不存在动画的保护。
- 切换姿态的同一轮不会执行 beats。

### TTS 没有声音

- 确认聊天抽屉的“语音”已勾选且音量不为 0。
- 在设置页运行“测试并播放 TTS”。
- 检查 Profile 是否为当前选中档案。
- 浏览器模式首次播放可能需要先点击页面，以满足自动播放策略。
- 检查返回格式是否与 Adapter 匹配；WAV 不能误设为 raw PCM。

### HF TTS 失败

- 检查服务是否在线或正在冷启动。
- 检查 Bearer Key、voice ID 和 `language`。
- HF 预设并发为 1，前一请求未结束时会排队。

### 本地 GPT-SoVITS 连接失败

先确认 API v2 正在监听：

```text
http://127.0.0.1:9880/tts
```

再检查本机 `ref_audio_path` 对 API 进程是否可读，以及 `prompt_lang / prompt_text / text_lang` 是否匹配模型。仅安装 Ryza Desktop Pet 不会自动启动 GPT-SoVITS。

### 日语语音模式只有中文或翻译失败

- 确认语言模式选择“中文回复 → 日语语音”。
- 此模式依赖当前 LLM 做翻译；LLM 不可用时 TTS 也无法开始。
- 自定义模板需引用 `speechLanguage`，否则服务可能仍按中文处理。
- 自定义 voice ID 不会自动推断；只有内置 HF 中英文 voice 对会自动切换。

### 角色或场景空白

- 第一次加载 4096 宽贴图可能需要数秒。
- 检查 GPU/WebGL 和 WebView2。
- 浏览器开发版查看开发者工具网络请求，确认 `.skel/.atlas/.png` 返回 200。
- 安装版应从随包资源读取；若文件缺失，重新安装当前完整 NSIS。

### 主窗口仍有 1 px 白边

当前版本已对主窗口设置 `shadow(false)`，设置窗口边框则是正常系统装饰。若桌宠窗口仍有白边：

1. 托盘“退出”旧实例。
2. 重新安装最新 NSIS。
3. 确认启动的是新安装目录中的程序，而不是旧构建。

### 设置保存失败

设置页会拒绝无效 URL、无效 JSON、重复 Profile ID、空 Profile 列表和越界数值。先按错误提示修复字段。仍无法保存时，检查 `%APPDATA%\RyzaPet` 是否可写。

## 7. 卸载与清理

从 Windows“已安装的应用”卸载程序。用户配置、长期记忆和截图附件位于 AppData，卸载器可能保留它们以便重装继续使用。

确认不再需要配置后，可手工删除：

```powershell
Remove-Item "$env:APPDATA\RyzaPet" -Recurse
```

执行前先备份需要保留的 Provider、系统提示词、长期记忆和会话，并从托盘退出应用。
